# Архітектура

## Принципи
- **Простота важливіша за масштаб.** Один процес, SQLite-файл, polling. Цього досить на сотні людей; переходити на вебхуки й Postgres варто, лише коли стане тісно.
- **Кейси — це дані, а не код.** Новий кейс = папка + запис у `cases.json`. Так само додаватимуться треки (бізнес-аналіз, QA тощо).
- **Людина в контурі рев'ю.** Бот не оцінює роботи сам. Автор пише рев'ю; тексти зберігаються, щоб пізніше порівняти AI-чернетки з людськими правками й вирішити, коли автоматизувати.
- **Вимірюємо власний продукт.** Кожен крок пишеться в таблицю `events`; воронка доступна в `/stats` і `/report`.

## Модулі `bot/`
| Файл | Відповідальність |
|---|---|
| `config.py` | шляхи, токен, ID автора, завантаження `cases.json` і `professions.json` |
| `storage.py` | SQLite: `users`, `attempts`, `submissions`, `events`; міграція зі старих CSV |
| `texts.py` | усі тексти бота (HTML), щоб правити копірайт без коду |
| `app.py` | обробники Telegram, нагадування, запуск |
| `report.py` | HTML-дашборд |

## Потік даних
```
/start ─► events(start) ─► вибір професії
  ├─ напрям «незабаром» ─► «Хочу цей напрям» ─► events(track_vote)
  └─ напрям, що працює ─► users.profession + events(profession_chosen)
  └─ картка кейсу ─► events(case_viewed)
       └─ «Беру кейс» ─► attempts + events(case_taken) ─► лист PM, бриф, CSV
            ├─ питання ─► events(question) ─► переслано автору ─► /reply
            └─ посилання/файл ─► «Так, здаю» ─► submissions + events(submission)
                 └─ автор: «Написати рев'ю» ─► submissions.review_text + events(review_sent)
                      └─ шаблон README + оцінка 1–5 ─► submissions.rating + events(rating)
нагадування: attempts без здачі, до дедлайну < 24 год ─► events(reminder)
```

## Відомі обмеження
- Стан «чекаю підтвердження здачі» й «пишу рев'ю» зберігається в пам'яті: після перезапуску людина просто надсилає роботу ще раз.
- Бот живе на ноутбуці автора з автозапуском (launchd). Коли з'являться перші зовнішні користувачі, переносимо на сервер.
- Усі отримують однакові дані кейсу. Для перших десятків людей це нормально; далі можна генерувати дані з різним seed для кожного.
